# DECISIONS

Every non-obvious choice made while building the showcase, with the reason. Newest at the bottom.

| ID | Decision | Reason |
|---|---|---|
| D01 | `_evidence_pack\` is read, linked and never modified. Shared logic is copied into `src\ttpmap\`. | Evidence base must stay as audited. |
| D02 | Local matcher retraining (CPU) was stopped during epoch 1; no weights were produced. All training moves to Colab notebooks. | Benchmark was about 2 h per epoch; instruction to stop. The partial epoch is not used anywhere. |
| D03 | `pytest` is not installed and the install was not permitted in this session. Tests are plain `test_*` functions with bare asserts, runnable with `pytest` and with `scripts\run_tests.py` (no dependencies). | Keeps the test gate checkable today; the gate records which runner ran. |
| D04 | Shipped tables contain sentence ids and SHA-256 of the text, never the text. Figures and tables quote at most short labelled excerpts. | Data licence is NOT-FOUND. |
| D05 | Every number in README, report and notebook text is rendered from `thesis_numbers.json` by a template; numbers are never typed. | Rule 1; makes the consistency scan meaningful. |
| D06 | One ranking rule everywhere: descending score, ties broken by lower label index (stable sort). | The notebooks use an unstable sort; at most 2 sentences are affected. |
| D07 | The fusion headline is NOT chosen here. Three definitions are carried with ids `B13a` (seed-averaged), `B12a` (seed-paired), `B12nb` (notebook: matcher seed varied). | Author's decision; all three reproduce. |
| D08 | New analyses are pre-registered in `experiments\prereg\` with a timestamp and SHA-256 before their script runs. Analyses that only restate evidence-pack results are labelled "re-analysis of seen results". | The test set has already been looked at many times; honesty about that is worth more than a pretended first look. |
| D09 | Comparison family for Holm = the 4 planned P@1 comparisons C1-C4 plus the 4 ablation contrasts = 8. | Stated before computing; in `experiments\prereg\01_statistics_family.md`. |
| D10 | Faithfulness sample = first 100 rows of `RandomState(42).permutation(725)`, the same fixed sample as the existing deletion test and rating sheet. | A rule fixed before this build; no hand selection. |
| D11 | Tactic mapping comes from ATT&CK v12.1 STIX downloaded earlier into `_evidence_pack\external\`; the showcase ships only the derived id-to-tactic table. | The project has no tactic data; file is 38 MB. |
| D12 | Rater identities appear nowhere; rating files are referenced by role and SHA-256 prefix. | Privacy rule. |
| D13 | Support-aware fusion was run in two pre-registered variants: 09 (three bands) and 13 (four bands, as in the author's plan of 14 Nov). Prereg 13 was sealed after the 09 script had run but before any support-aware number was read. Both are reported; Holm over the 4 tests of that family. | The author's band layout arrived after 09 was sealed; hiding either run would be a forking path. |
| D14 | The draft's number audit was done from the ledger the author pasted, transcribed to `results/number_audit/ledger_from_author_paste.csv`, because the .docx is not on this PC. The author's `audit_numbers.py` is shipped unchanged and must still be run on the real file. | Do not claim an audit of a file that was not read. |
| D15 | Tables in generated documents may take rows straight from `results/*.csv` (by script); single numbers in prose always go through a claim id. | Per-bucket and per-setting tables would otherwise need hundreds of ids. |
| D16 | The number-consistency gate uses the author's matching rule: a token passes if it equals ANY number in `thesis_numbers.json` (values, displays, CIs, and numbers inside definitions) or is on `configs/number_whitelist.txt`. It catches stray numbers, not a right number in the wrong place. | Stated so the gate is not over-read. |
| D17 | Hash manifest excludes run logs (`test_report.json`, `smoke_logs/`, `qa_gates.json`) because they contain timings. | They change on every run by design. |
| D18 | Notebooks embed the source of `ttpmap.metrics`, `fusion` and `stats` (copied by the generator) instead of importing the package. | The repository is private and Colab cannot install it; one source, no drift. |
| D19 | Human-study sheets and their key are generated locally and excluded from git and the zip. | They contain dataset sentences and the real/control assignment. |
| D21 | GPU notebooks (02, 03, 04, 06, 08) stop in the first cell without a GPU unless SMOKE is set; CPU notebooks (00, 01, 05, 07, 09, 10) only print a note. | Stopping a 1-minute CPU analysis on a CPU runtime helps nobody. |
| D22 | The new per-epoch checkpoint and resume code of notebook 03 runs only on a GPU and is UNTESTED; the smoke run skips that cell on CPU. The matcher resume code (notebooks 04, 08) is exercised by the smoke run. | No classifier training on this PC. |
| D20 | CI files live in `_showcase/ci/` as UNTESTED templates, not at the repository root. | Only `_showcase/` and `_evidence_pack/` are versioned; nothing here was executed. |
| D23 | Local LLM baseline (prereg 17) runs with 9 of 29 layers on the GTX 960 and the rest on the CPU, pinned with `TTPMAP_OLLAMA_NUM_GPU=9` from 05:23 on 15 Nov; requests go to `127.0.0.1` instead of `localhost`. | Benchmark on dev prompts (`results/llm_raw/bench_placement.csv`): CPU only 16.5 s per request, 9 layers 10.8 s, 12 layers 10.4 s, 14 layers 10.3 s; 12 and 14 layers changed the answer on 1 of 3 prompts, and 14 layers used 3.85 of 4 GB. The whole model (about 5.5 GB) does not fit in 4 GB, so GPU-only is impossible. 9 layers is the placement Ollama chose automatically for the complete `closed` variant (server.log: output layer + 8 repeating layers), so all three variants share one placement. `localhost` first tried IPv6 and fell back after 2.0 s on every request; 127.0.0.1 removes that without touching prompts or options. Every row from 05:23 records `num_gpu`; earlier rows (closed, first 2 of rr_matcher) used the identical automatic fit. |
| D24 | Headline fusion number = `B13a` (seed-averaged components, one system, 95% CI); `B12a` (seed-paired, mean +/- sd over seeds 42-44) is reported beside it as the seed-robustness figure. | Author decision of 15 Nov 2026. Every other row of the main table is also a 3-seed ensemble, so the table uses one convention. |
| D26 | Prereg 17 outcome: no LLM variant (qwen2.5:7b, closed / rr_matcher / rr_zero) beats the matcher ensemble; all six comparisons favour the matcher or the fusion with Holm p < 0.05 (`L1.*`, `results/llm_baseline.csv`, `llm_family.csv`). The hypothesis "an open 7B LLM does not beat the matcher" is supported. | Scored by `finish_q1.ps1` at 11:46 on 15 Nov 2026 after the unattended run; the result is a lower bound on LLM performance (one local 7B model), consistent with arXiv 2606.18166. |
| D27 | Wave 2 (preregs 18 and 19) is reported as sealed: components are the z-scored rows of `ttpmap.fusion.components`. A POST-HOC, not pre-registered sensitivity scores the classifiers with raw probabilities / SVM decision scores (`scripts/run_conformal_posthoc.py`, `results/conformal_posthoc_raw.csv`, `results/selective_posthoc_raw.csv`). | In the z-scored rows the 553 labels outside a classifier's 180-label space get z = 0, above its own low-probability labels, so a conformal set that must cover the classifier's misses takes them all (sets of about 558 labels). That is a property of the representation, not of the classifier, and a reader must see both. The fusion comparison (prereg 18 H2) is unaffected in direction: the fusion's sets stay the smallest. |
| D28 | Description similarity (`A11.sim_*`, wave 2 `AD1`) is computed with `difflib.SequenceMatcher(..., autojunk=False)`, ATT&CK text first. The A11 values registered at 05:43 on 15 Nov used the default `autojunk=True` and are replaced (median and count below 0.80 change; the id-set result does not). | Code review of 15 Nov 2026: with autojunk on, characters that occur in more than 1% of a 200+ character string are ignored as junk, which deflates character-level ratios and makes them depend on argument order. Checked: with autojunk off both argument orders give the same median. |
| D25 | No git commits or pushes in this project from 15 Nov 2026 on. | Author instruction: the work belongs to another person's project and the author's identity must not be attached to it. The LLM supervisor's final commit step was removed. |
| D29 | Explainer app (`..\ttp_app`, thesis objective c, first written in claude.ai): the triage thresholds use the prereg-19 order statistic of the dev margins (`core.dev_threshold`, same rule as `ttpmap.selective.dev_threshold_for_coverage`) instead of `np.quantile`. Technique names come from the ATT&CK v12.1 bundle (label-space release), then `confusions.csv`, then the latest-release name file; deprecated techniques say "no replacement" instead of naming themselves as successor; retired labels inside the conformal set are flagged, not only the top-1. | First run of `verify_artifacts.py` on this PC (15 Nov 2026): 15/16, triage coverage at 0.9 was 0.9117 vs 0.9145 because `np.quantile` interpolates between order statistics. After the fix 16/16. Names: before the fix only 60 of the 733 labels had a name (those in `confusions.csv`), now 733; 17 v12.1 names differ in the latest release (e.g. T1574.001). Each fix has a test (`ttp_app/tests/test_core.py`; 26 app tests); code review of 15 Nov: `TTPMAP_DEMO=0` no longer turns demo mode on. |
| D30 | Draft numbers are audited on the real `Thesis_Draft_v2.2.docx` (project root) with `scripts/audit_loop.py`, which now also looks for `Thesis_Draft*.docx` in the root and writes one folder per draft (`results/number_audit_v2_2/`); the ledger dry run in `results/number_audit/` is kept. Dataset statistics quoted by the draft are registered (`A2.labels_all`, `A2.labels_per_text`, `A2.words_mean`). New `scripts/check_intervals.py` (5 tests) compares every written confidence interval with the registry claim it belongs to; `audit_loop.py` adds its DIFFERS rows to AUDIT_TODO. | The .docx was found in the root on 15 Nov 2026 (earlier sessions looked only in `thesis\`). 193 labels and 1.16 labels per sentence are confirmed by the data; "23 tokens" (p370) is not reproduced by any common tokenisation (whitespace 21.0, words 22.5, RoBERTa sub-words 34.1) and is left for the author. The value-by-value audit missed most of the 13 intervals with wrong numbers (the old 1,000-resample values) because a wrong bound often equals some other registered number. |
